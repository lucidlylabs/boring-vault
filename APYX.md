# Apyx Yield USD — BoringVault Deployment

This is a proof-of-concept BoringVault deployment for the Apyx.fi ecosystem
(apyUSD, apxUSD) on an Ethereum mainnet anvil fork. The vault whitelists five
strategist action families via a merkle tree, proves each one works end-to-end
against the actually-deployed architecture, and proves that anything outside
the whitelist reverts.

The intent is to mirror a production run closely enough that the same scripts,
with the same config, would produce the same result on real mainnet — the only
thing that would change is the RPC URL and the ownership handover at the end.

---

## What the vault can do

Five action families are encoded as leaves in the strategist merkle tree.
Anything not listed here will fail the proof check and revert.

| # | Action                | What it wraps |
| - | --------------------- | ------------- |
| 1 | Mint apyUSD           | ERC4626 `approve` / `deposit` / `withdraw` / `mint` / `redeem` on the apyUSD wrapper over apxUSD |
| 2 | Pendle LP             | SY mint/redeem, PT/YT mint/redeem, and LP add/remove on the apxUSD Pendle market |
| 3 | Curve apxUSD/USDC     | `exchange`, `add_liquidity`, `remove_liquidity` on the stable-ng factory pool |
| 4 | Morpho Blue           | `supplyCollateral` (apyUSD), `borrow` (USDC), `repay`, `withdrawCollateral` |
| 5 | Accountant fees       | `updateExchangeRate` + `claimFees` in USDC |

All five are generated by
[CreateApyxUSDMerkleRoot.s.sol](script/MerkleRootCreation/Mainnet/CreateApyxUSDMerkleRoot.s.sol)
and exercised by
[ApyxStrategistIntegration.t.sol](test/integrations/ApyxStrategistIntegration.t.sol).

## Runbook

```bash
# 1. Start an anvil fork of mainnet.
anvil --fork-url $ETHEREUM_RPC_URL &

# 2. Pre-step: deploy a user-owned Deployer + RolesAuthority and patch
#    the Apyx config. Needed because the shared mainnet Deployer at
#    0x771263...75FC is gated to Veda's whitelisted callers.
export BORING_DEVELOPER=<anvil private key>
export MAINNET_RPC_URL=http://127.0.0.1:8545
forge script script/ArchitectureDeployments/DeployApyxDeployer.s.sol:DeployApyxDeployerScript \
  --rpc-url $MAINNET_RPC_URL --broadcast

# 3. Deploy the full architecture (BoringVault, Manager, Teller, Accountant,
#    Queue, Solver, RolesAuthority, Pauser, Timelock, Lens) via the
#    config-driven deploy.
forge script script/ArchitectureDeployments/DeployApyxVault.s.sol:DeployApyxVaultScript \
  --sig 'run(string)' 'Mainnet/ApyxUSD.json' \
  --rpc-url $MAINNET_RPC_URL --broadcast

# 4. Deploy the ApyxUSDDecoderAndSanitizer.
forge create src/base/DecodersAndSanitizers/ApyxUSDDecoderAndSanitizer.sol:ApyxUSDDecoderAndSanitizer \
  --rpc-url $MAINNET_RPC_URL --private-key $BORING_DEVELOPER --broadcast

# 5. Generate the strategist merkle root + leaves JSON.
forge script script/MerkleRootCreation/Mainnet/CreateApyxUSDMerkleRoot.s.sol:CreateApyxUSDMerkleRoot \
  --rpc-url $MAINNET_RPC_URL -vvv

# 6. Run the integration + E2E tests.
forge test --match-contract ApyxStrategistIntegrationTest \
  --fork-url $MAINNET_RPC_URL --skip 'script/DeployAdapters.s.sol' -vvv
forge test --match-contract ApyxDeployedE2ETest \
  --fork-url $MAINNET_RPC_URL --skip 'script/DeployAdapters.s.sol' -vvv
```

A couple of things that will bite you if they're wrong:

- `MAINNET_RPC_URL` must point at anvil throughout. The deploy script calls
  `vm.createSelectFork("mainnet")`, which resolves via `rpc_endpoints.mainnet`
  in `foundry.toml` — if that's pointing at real mainnet the script won't see
  the Deployer you just put on the fork.
- `--skip 'script/DeployAdapters.s.sol'` sidesteps unrelated repo rot: a
  `MorphoLoopTvlAdapter` call site that hasn't been updated for a newer
  5-argument constructor. Nothing to do with Apyx.

## Tests

### [ApyxStrategistIntegration.t.sol](test/integrations/ApyxStrategistIntegration.t.sol)

Spins up a fresh vault + manager + roles in `setUp()`. This isolates the
strategist behaviour from whatever state a particular deploy happens to be in.
One test per action family:

| Test                                  | What it proves |
| ------------------------------------- | -------------- |
| `testStrategistMintApyUSD`            | approve (apxUSD → apyUSD) + deposit mints shares to the vault |
| `testStrategistPendleMintSy`          | apxUSD mints SY via the Pendle router |
| `testStrategistCurveAddLiquidity`     | `add_liquidity` on apxUSD/USDC returns LP tokens to the vault |
| `testStrategistMorphoSupplyAndBorrow` | `supplyCollateral`(apyUSD) + `borrow`(USDC) against the live market |

### [ApyxDeployedE2E.t.sol](test/integrations/ApyxDeployedE2E.t.sol)

Drives the *deployed* architecture (addresses above) instead of a fresh one.
Two tests:

| Test                                         | What it proves |
| -------------------------------------------- | -------------- |
| `test_E2E_mintApyUSD_onDeployedArchitecture` | Admin grants STRATEGIST_ROLE (7) and setManageRoot on the deployed Manager; a strategist EOA with no admin privileges successfully mints apyUSD via `manageVaultWithMerkleVerification` |
| `test_E2E_unauthorizedAction_reverts`        | Same setup, but the strategist submits a USDT approval (no matching leaf). Reverts with `ManagerWithMerkleVerification__FailedToVerifyManageProof` |

### User-owned Deployer pre-step

 [DeployApyxDeployer.s.sol](script/ArchitectureDeployments/DeployApyxDeployer.s.sol)
deploys a fresh Deployer and RolesAuthority owned by `BORING_DEVELOPER`, then
patches the Apyx config to point at it.

Three details are load-bearing here:

1. `DEPLOYER_ROLE` has to be granted to **both** the owner EOA *and* the
   Deployer contract itself. `bundleTxs` relays inner calls with
   `msg.sender = deployer`, so the contract needs its own role.
2. `deploymentOwnerAddressOrName.address` must be the Deployer contract, not
   the owner EOA. Every new contract's `Auth.owner` gets set to
   `deploymentOwner` at construction, and bundled admin calls need to pass
   each contract's `requiresAuth` check with `msg.sender = Deployer`.




### Test against the *deployed* architecture, not a fresh one

The integration test (fresh vault per `setUp`) proves the *code* works. The
E2E test proves the *deployed system* works — it grants the role, sets the
root, and executes a whitelisted action on the real anvil-deployed Manager,
using a strategist EOA that holds no admin privileges. This is the closer
analogue to a real production run: if it passes here, a mainnet rehearsal
with the same scripts and config should behave the same way.
